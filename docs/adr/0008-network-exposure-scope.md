# ADR-008. 외부 네트워크 노출 범위

- **Status**: 부분 확정 — 443/80 공개, 8080은 IP 화이트리스트, LLM Gateway 무인증 노출이 남은 리스크
- **이전 Status**: 대기 중

## Context

서버가 완전 폐쇄망이라 방화벽에서 열어야 할 포트 수를 확인함. 또한 학교망에서 도메인 주소는 하나 받되, 그 도메인/공인 IP의 외부 443이 다른 부서·서비스와 공유되어 이미 선점되어 있을 수 있어 **외부 노출 포트 번호는 우리 쪽에서 정해야 하는 상황**임.

## Decision

Ingress가 Host/path 기반으로 여러 백엔드(GUI, 관리서버, 필요 시 Gitea/Registry 웹 UI)를 하나의 443 리스너로 통합 라우팅하므로, **외부(사용자 PC 쪽 네트워크 구간)에는 포트 1개만 개방**하면 된다는 원칙은 유지. 실제 포트 번호는 아래 우선순위로 결정.

1. 학교 네트워크팀에 확인해서 **해당 도메인/IP의 외부 443이 비어있으면 `443 → 443` DNAT**으로 매핑 (사용자가 포트 번호 없이 `https://ops.internal`로 접속 가능 — 가장 깔끔, 원 구성도의 "HTTPS 443"과도 일치)
2. 이미 다른 서비스가 443을 선점하고 있으면, **대체 포트를 골라 `<대체포트> → 443` DNAT**으로 매핑
   - 방화벽/공유기의 포트포워딩(DNAT) 규칙 하나로 처리 — 외부에서 보이는 포트/IP와 내부 실제 포트(443)가 달라도 무방하며, 이는 DNAT이 목적지 IP·포트를 바꿔 전달해주기 때문
   - **`6000`, `6665~6669`, `6697` 등은 사용 금지** — Chrome/Firefox가 프로토콜 혼동 공격 이력이 있는 포트로 간주해 `ERR_UNSAFE_PORT`로 접속 자체를 차단함
   - 대안으로 `7000` 또는 `8000` 권장 (브라우저 차단 목록에 없고 대체 HTTP 포트로 통상적으로 쓰이는 대역)
   - K8s NodePort 서비스로 직접 노출하는 게 아니라 **방화벽/공유기 레벨의 DNAT**으로 처리하므로, NodePort 기본 대역(30000~32767) 제약과는 무관

## Consequences

- `kube-apiserver`(6443)와 metrics-server 통신은 클러스터 내부(Calico VXLAN 오버레이)에서만 이루어지며, 네트워크 세그멘테이션 방화벽이 별도로 있는 경우에만 6443을 추가로 열면 됨.
- 외부 인터넷 아웃바운드는 0개 — 패키지/모델은 오프라인 반입(crictl + containerd import)이라 애초에 아웃바운드 자체가 불필요함(구성도의 "외부 인터넷 API 기본 차단"과 일치).
- 실제 배정받는 포트가 443이 아니면, 사용자 안내 문서/URL에 포트 번호(`:8000` 등)를 항상 포함해야 함.
- 관련: [0005](0005-domain-routing-strategy.md), [0007](0007-ingress-controller-choice.md)

## 현황 갱신 (2026-11-03, 실제 클러스터 조회 기준)

- 실제 노출 현황: MetalLB `lb-pool`(10.0.0.21~27) 중 5개를 Gateway가 사용한다.
- 공개 포트는 80/443이다(`infra-gateway`는 HTTP→HTTPS 리다이렉트 적용). 8080은 NetworkPolicy로 지정 IP(/32)만 허용한다.
  - `rag-gateway-8080-restrict`: 192.0.2.23, .115, .116, .118, .119, .120
  - `vkey-gateway-8080-restrict`: 192.0.2.23, .115, .120, .122
- **남은 과제**: LLM 추론 경로의 Gateway 2개(`ai-gateway`, `kserve-ingress-gateway`)는 인증 정책을 아직 적용하지 않았다. 외부 도달 여부를 점검한 뒤 ClusterIP 전용 전환 또는 SecurityPolicy(API Key) 적용을 계획 중이다. 전환 전에 `rag-server`의 LLM 호출 주소를 LB IP에서 클러스터 내부 Service 주소로 바꾼다.
- 원 결정의 "외부 인터넷 아웃바운드 0개" 전제는 현재와 다르다. GPU 드라이버가 부팅 시 커널 헤더를 외부에서 내려받는다([0044](0044-kernel-pin-highpoint-driver.md)).
